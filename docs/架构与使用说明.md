# 架构与使用说明

> 适用：把 EonTest 的 UDS/DoIP 配置与解码能力嵌到 JEMSts。
> 目标：**同一张测试工步表（G 列配置参数1 + P 列解码配置），EonTest 与 JEMSts 共用。**

## 1. 结论：用 C# 函数库 + 薄脚本，不用纯脚本

JEMSts 的脚本是"测试控制语言"，不适合承载 TCP/DoIP 组帧、会话复用、字节解码、0x78/0x08 处理。
正确做法是**按 JEMSts 自己的扩展机制**——写一个函数库（`JabilTest.Test` 子类），脚本每步只写一行调用。

```
脚本层(薄)  ──►  UdsFunctionLibrary (Test 子类, JEMSts 反射加载)
                      │
                      ▼
                 UdsCore (UDS/DoIP 引擎 DLL, 无 JEMSts 依赖)
                    ├─ DoipClient         : TCP + 路由激活 + 诊断消息 + ACK/NACK + 0x78
                    ├─ CanIsoTpTransport  : CAN/ISO-TP 收发 + 0x78 后等待最终响应
                    ├─ UdsRequestExecutor : 序列/重试/0x08 恢复/expected 匹配/解码
                    ├─ DoipSessionPool    : 跨步骤复用 TCP 连接 (connectionMode=session)
                    ├─ UdsStepConfig      : G 列→UDS 配置模型
                    └─ ExcelStepExtensions: IsUdsStep/ToStepConfig/设备表回填 (UDS 侧)
                      │
                      ▼
           ExcelDecodeCore (共享引擎 DLL, 协议无关)
              ├─ MiniXlsx / ExcelStepReader : 无依赖读共享 Excel (方案C)
              ├─ ResponseDecoder / DecodeSpec : 截取/转换/公式 (P 列)
              ├─ ConfigPairParser / HexUtils / MiniJson / FormulaEvaluator
              └─ (其它硬件协议库 Modbus/CAN/串口... 也引用本 DLL)
```

## 2. 分层职责（对齐 EonTest 的既有原则）

| 层 | 职责 | EonTest 对应 |
|---|---|---|
| 通信层 | TCP 连接、DoIP 组帧/解帧、路由激活 | `TcpBusDriver` + `DoipProtocolLayer`（组帧部分） |
| 协议层 | UDS 收发、expected 匹配、0x78 延长超时、NACK 0x08 重建会话+回放 `10 xx`、31 01 失败先 31 02 停止、3E 保活、相邻请求间隔 | `DoipProtocolLayer::sendDiagnosticMessage` + `DoipMasterPlugin` |
| 解码层 | offset/length/endian/type/bits/string/formula | `ResponseDecoder` |
| 配置层 | G 列 key=value、P 列 JSON/内联/Profile | `XlsxParser::parseConfigPairs` + 插件配置键 |
| 脚本层 | 每步一行函数调用 | （JEMSts 侧新增） |

## 3. 三种接入方式（渐进式）

1. **配置驱动单步** `DoIP_UDS_Step(G列, P列, ECU键)` —— G/P 列原文传参，最贴近 EonTest 语义；
2. **Excel 直读单步** `DoIP_UDS_ExcelStep(excel, sheet, 工步号)` —— 库内读共享表该行的 G/P 列执行；
3. **Excel 一键全跑** `DoIP_UDS_ExcelRunAll(excel, sheet)` —— 整张表的 UDS 步骤按顺序跑，自动复用会话。

> 会话键默认取"设备名称"（如 `DoIP_ECU`）。同一个键的多步共享一个 TCP 连接；
> 与 EonTest 一样，**第一条步骤写全地址参数，后续步骤只写业务参数**。

## 4. 关键机制说明

- **会话复用**：`DoipSessionPool` 按 ECU 键缓存 `DoipClient`；`connectionMode=session` 时跨步骤复用，`perStep` 时每步新建。
- **NACK 0x08 恢复**：发送失败且错误含 `0X08` 时，关闭并重建 TCP + 路由激活，回放已成功的 `10 xx` 会话控制，再重发当前指令（对应你们 0x08 的解法）。
- **0x78 Response Pending**：收到 `7F <请求 SID> 78` 后，在当前请求中继续接收，直到最终响应或 pending 超时；pending 报文本身不会触发重新发送，也不会发送 `31 02`。CAN 和 DoIP 均支持此等待；DoIP NACK `0x08` 恢复仍只适用于 DoIP。
- **31 01 例程**：失败重试前先发 `31 02` stopRoutine；整序列失败也做 `31 02` 清理。
- **保活**：主线程空闲时（下一条请求前）发 `3E 80`（默认抑制响应，只发不读）。
- **相邻间隔**：同一会话连续请求至少 `minRequestIntervalMs`（默认 20ms）。

## 5. 部署

```
Modules\UserLibraries\
   ├── ExcelDecodeCore.dll       # 共享引擎（Excel/解码/配置，其它协议库也引用）
   ├── DoipCore.dll              # UDS/DoIP 引擎
   └── DoipFunctionLibrary.dll   # 函数库（Test 子类）
```

> **为什么 3 个 DLL 能行**：`JEMSts.exe.config` 的 `<probing privatePath>` 已包含
> `Modules\UserLibraries`，JEMSts 发现阶段（临时 AppDomain 按名加载）和运行阶段
> （`Assembly.LoadFile`）都能解析 ExcelDecodeCore / DoipCore 依赖。
> 已用 `tools/LoadProbe` 按 JEMSts 的发现机制实测通过（`PROBE OK: concrete=8`）。
> 无需签名/校验。

解码 Profile：放在 Excel 同目录 `DecodeProfiles\` 或 Excel 同目录。

## 6. 失败处理策略（ZLG 风格）

本库**所有函数都不会因失败而终止 JEMSts 脚本**：

- 函数永远返回 `TestStatus.Pass`，真实成败状态放在返回值里（`$status` / `ReturnValue9`）；
- 由脚本自行判断：继续、停机、记录、跳转；
- 与现有 `ZUDS_Request` 的用法一致（`if($status == 0 && $type == 1){ ... }`）。

> 背景：JEMSts 主循环（`TestScript.cs`）中，函数返回 `TestStatus.Fail` 且非测量项时，脚本会立即 `break` 终止。
> 为避免一个 UDS 步骤失败卡死整条序列，库函数不设 Fail，把状态交给脚本。

## 7. 安全边界

- 公式仅允许：数字、`x`、`+ - * / %`、括号、`abs/min/max/round/floor/ceil`；禁止文件/网络/脚本/反射。
- 解码 Profile 只按白名单目录解析，不解析任意绝对路径（除非显式给绝对路径）。
- XLSX 读取为只读，不改写任何文件。
